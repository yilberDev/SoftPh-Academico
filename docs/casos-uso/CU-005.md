## Correspondencia con la implementación actual

> **Nota histórica (actualizada el 2026-10-10).** La descripción de esta sección se redactó como «caso de uso derivado» antes de localizar y transcribir la ficha oficial. Su nota original decía: «El documento académico nombra CU-005 en la matriz de trazabilidad (módulo *Feedback / PQRS*, actor Administrador), pero no incluye su descripción detallada.» Esa afirmación ya no es vigente: el documento académico incluye la ficha de CU-005 en la Tabla 49, transcrita arriba (verificada en la auditoría de las fichas de casos de uso del 2026-10-10). La descripción se conserva como correspondencia con la implementación, no como parte de la ficha. Sigue la *Plantilla para descripción detallada de casos de uso* aprobada y aplica las decisiones registradas en [extensiones de diseño](../extensiones-diseno.md) (HU-005). No incluye funciones del residente (HU-009).

### Diferencias con la ficha oficial

- **Nombre y actor:** coinciden (Gestionar feedback; Administrador).
- **Flujo principal:** la ficha tiene **diez pasos**: listar, seleccionar, responder (validar y almacenar), marcar como resuelto con una nota, actualizar el estado y notificar al residente. La versión derivada tiene **trece**: añade la búsqueda, el filtro, el orden y la paginación del listado, el historial de acciones, el correo al responder y una **confirmación** antes de resolver (pasos 10 y 11).
- **Excepciones:** 3a (sin feedback) y 5a/7a (respuesta o resolución sin la información requerida) están cubiertas (listado vacío; respuesta o nota vacía o de más de 2000 caracteres). La implementación añade: feedback inexistente, **modificación concurrente desde otra sesión**, feedback ya resuelto, fallo del correo, cancelación de la confirmación y sesión o rol no válidos.
- **Precondición y postcondición:** coinciden en exigir feedback registrado; la implementación pide una sesión de administrador y detalla la notificación, la auditoría y que el mensaje original no cambia.
- **Relaciones:** la ficha relaciona solo CU-017; la implementación añade CU-002, CU-009 y CU-018.

| Actores | Administrador. |

#### Secuencia normal

| Paso | Actor | Software |
|---|---|---|
| 1 | Selecciona "Feedback" en el panel de administración. | |
| 2 | | Comprueba la sesión y el rol (CU-018) y muestra "Cargando feedback..." y luego el listado paginado: residente, asunto, fecha, estado y categoría y urgencia ("No registrada" en el feedback anterior a HU-009), del más reciente al más antiguo. |
| 3 | Busca por residente o asunto, filtra por estado, ordena por una columna o cambia de página. | |
| 4 | | Muestra los registros que corresponden. |
| 5 | Selecciona "Ver detalle" de un feedback. | |
| 6 | | Muestra el residente (nombre, correo y unidad actual), el asunto, la fecha, el mensaje original con su categoría y urgencia, el estado, la respuesta y la nota de resolución si existen, y el historial de acciones. |
| 7 | Escribe la respuesta para el residente y la guarda. | |
| 8 | | Guarda la respuesta, la registra en la auditoría, confirma "Respuesta guardada y enviada al residente.", envía el correo al residente con la respuesta y actualiza el detalle y el historial. |
| 9 | Escribe la nota de resolución y selecciona "Marcar como resuelto". | |
| 10 | | Pide confirmar la resolución. |
| 11 | Confirma. | |
| 12 | | Marca el feedback como resuelto con la fecha y hora, guarda la nota interna, lo registra en la auditoría, notifica al residente (con la respuesta si existe, sin la nota interna) y muestra el estado Resuelto, la confirmación y el historial actualizado. |
| 13 | | El caso de uso termina. |

#### Excepciones

| Paso | Software |
|---|---|
| 2, 4 | Si no hay feedback, informa "No hay feedback registrados."; si ninguno coincide, "No se encontraron registros con los filtros seleccionados."; si no se puede cargar, lo informa y ofrece "Reintentar". |
| 6 | Si el feedback no existe, informa "Este feedback no existe." |
| 7, 9 | Si la respuesta o la nota está vacía o supera 2000 caracteres, lo indica junto al campo y no guarda nada. |
| 8, 12 | Si otra sesión modificó el feedback antes, informa "El feedback fue actualizado en otra sesión. Vuelve a cargar la información antes de realizar cambios.", recarga el detalle y no guarda nada. |
| 8, 12 | Si el feedback ya fue resuelto, informa "Este feedback ya fue marcado como resuelto." y no permite responder ni volver a resolverlo. |
| 8, 12 | Si el correo no se puede enviar, el cambio queda guardado; se registra el fallo en la auditoría y se informa "Los cambios quedaron guardados, pero no fue posible enviar la notificación al residente." |
| 11 | Si cancela la confirmación, el feedback sigue pendiente. |
| 2–12 | Si la sesión terminó, lleva al inicio de sesión; si el usuario no es administrador, informa que no tiene permiso (403) y no muestra datos. |
