# CU-018 — Controlar acceso según el rol

> **Caso de uso derivado.** El documento académico nombra CU-018 en la matriz de trazabilidad (módulo *Seguridad*, actores Administrador / Residente), pero no incluye su descripción detallada. Esta descripción sigue la *Plantilla para descripción detallada de casos de uso* aprobada y describe el control de acceso real del sistema, según las decisiones de [extensiones de diseño](../extensiones-diseno.md). No añade funcionalidades a HU-018 / RF-018.

| Campo | Descripción |
|---|---|
| Identificador de caso de uso | CU-018 |
| Nombre | Controlar acceso según el rol |
| Descripción | En cada solicitud a una página o a una funcionalidad, el sistema identifica al usuario por su sesión, determina su rol (ADMINISTRADOR o RESIDENTE) y solo permite las funcionalidades y la información que corresponden a ese rol. |
| Actores | Administrador, Residente. |

## Secuencia normal

| Paso | Actor | Software |
|---|---|---|
| 1 | Inicia sesión con el login único (CU-002 o CU-007). | |
| 2 | | Crea la sesión en el servidor y lleva al usuario al área de su rol: el administrador a `/admin`, el residente a `/resident`. |
| 3 | Abre una página o usa una funcionalidad. | |
| 4 | | Identifica la sesión por la cookie (sin aceptar identidad ni rol enviados por el navegador) y comprueba que siga vigente y que la cuenta siga activa. |
| 5 | | Lee el rol de la cuenta y comprueba que la funcionalidad corresponde a ese rol: al administrador, la estructura de unidades (CU-013) y las invitaciones de residentes (CU-003); al residente, su panel y sus propios datos. |
| 6 | | Atiende la solicitud y muestra solo la información que corresponde al rol; al residente, únicamente la suya. |
| 7 | | El caso de uso termina. |

## Excepciones

| Paso | Software |
|---|---|
| 4 | Si no hay sesión, o la sesión no existe, fue cerrada, fue revocada por un cambio de contraseña o venció (8 horas, o 30 minutos sin actividad), o la cuenta fue deshabilitada o eliminada: una página protegida lleva al inicio de sesión; la API responde 401 "Debes iniciar sesión para continuar." |
| 5 | Si la funcionalidad no corresponde al rol (p. ej., un residente en `/admin` o en la API de estructura o de invitaciones, o un administrador en `/resident`): la página muestra "Acceso no autorizado" (403) sin su contenido; la API responde 403 "No tienes permiso para realizar esta acción." y no lee ni cambia nada. |
| 5 | Si la solicitud trae un rol, un usuario o un identificador de recurso manipulados: se ignoran para decidir el acceso; el resultado es el del paso 5 con el rol real. Un identificador de un recurso que no le corresponde recibe el mismo 403 exista o no, sin revelar su existencia. |
| 5 | Si es una modificación sin el origen público o sin el token CSRF de la sesión: se rechaza (403) y no cambia nada. |
| 4 | Si no se puede comprobar la sesión (servicio no disponible): la página no se muestra y se informa que el servicio no está disponible. |

## Relaciones

| Campo | Descripción |
|---|---|
| CU relacionados | CU-002 Iniciar sesión como administrador y CU-007 Iniciar sesión como residente (preceden); CU-003 y CU-013 (funcionalidades del administrador que protege); CU-016 y CU-019 (públicos, con su enlace de un solo uso). |
| Precondición | El usuario tiene una cuenta activa con rol ADMINISTRADOR o RESIDENTE. |
| Postcondición | El usuario solo accedió a las funcionalidades y a la información de su rol; las solicitudes rechazadas no cambiaron ningún dato. |
