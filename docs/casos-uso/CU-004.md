# CU-004 — Registrar pago manual

> **Caso de uso derivado.** El documento académico nombra CU-004 en la matriz de trazabilidad (módulo *Gestión de pagos*, actor Administrador), pero no incluye su descripción detallada. Esta descripción sigue la *Plantilla para descripción detallada de casos de uso* aprobada y aplica las decisiones registradas en [extensiones de diseño](../extensiones-diseno.md) (HU-004). No añade funcionalidades a HU-004 / RF-004.

| Campo | Descripción |
|---|---|
| Identificador de caso de uso | CU-004 |
| Nombre | Registrar pago manual |
| Descripción | Permite al administrador registrar un pago realizado por un residente, aplicarlo a las obligaciones pendientes de su unidad, enviarle el recibo en PDF y consultar el resumen de los pagos registrados. |
| Actores | Administrador. |

## Secuencia normal

| Paso | Actor | Software |
|---|---|---|
| 1 | Selecciona "Pagos" en el panel de administración. | |
| 2 | | Comprueba la sesión y el rol (CU-018) y muestra el formulario "Registrar pago" y el resumen de pagos. |
| 3 | Busca al residente por nombre o documento y lo selecciona. | |
| 4 | | Muestra, de forma informativa, la unidad donde vive el residente. |
| 5 | Ingresa el monto, elige el método de pago (efectivo, tarjeta o transferencia), el concepto (mensualidad, mora, penalización u otro, con su descripción) y la fecha del pago, y confirma. | |
| 6 | | Determina la unidad vigente del residente, registra el pago con la fecha y hora de ingreso y lo aplica a las obligaciones pendientes de la unidad, de la más antigua a la más reciente; lo que sobra queda como saldo a favor. Registra la operación en la auditoría. |
| 7 | | Confirma "Pago registrado correctamente." con el número de recibo, el monto, el valor aplicado, el saldo a favor (si lo hay), el estado del pago y el saldo resultante de la unidad. |
| 8 | | Genera el recibo en PDF y lo envía como adjunto al correo del residente. |
| 9 | | Actualiza el resumen de pagos. |
| 10 | Consulta el resumen, lo filtra por residente o por fechas, lo ordena por una columna o cambia de página. | |
| 11 | | Muestra los pagos que corresponden: nombre del residente, concepto, monto, método, fecha y estado. |
| 12 | | El caso de uso termina. |

## Excepciones

| Paso | Software |
|---|---|
| 5 | Si falta un campo obligatorio o un valor no es válido (monto no numérico, menor o igual a cero o con más de 2 decimales; método o concepto no permitido; concepto «Otro» sin descripción; fecha inválida o posterior a hoy), indica junto a cada campo lo que debe corregirse y no registra nada. |
| 6 | Si la persona seleccionada no es un residente registrado con una residencia vigente (por ejemplo, una invitación sin activar), lo indica y no registra nada. |
| 6 | Si la residencia del residente cambia mientras se registra el pago, lo indica y pide intentarlo de nuevo, sin registrar nada. |
| 6 | Si no hay obligaciones pendientes, el pago queda completo como saldo a favor (estado "Saldo a favor"). |
| 8 | Si el recibo no se puede generar o enviar, el pago queda registrado igualmente; el sistema lo registra en la auditoría y muestra, aparte de la confirmación, "El pago fue registrado, pero no fue posible enviar el recibo al correo." |
| 2–11 | Si la sesión terminó, lleva al inicio de sesión; si el usuario no es administrador, informa que no tiene permiso y no registra ni muestra datos. |
| 11 | Si no hay pagos, informa "No hay pagos registrados."; si ninguno coincide con los filtros, "No se encontraron pagos con los filtros seleccionados."; si no se puede consultar, lo informa y ofrece "Reintentar". |
