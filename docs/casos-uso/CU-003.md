# CU-003 — Invitar residente

> **Caso de uso derivado.** El documento académico nombra CU-003 en la matriz de trazabilidad (módulo *Gestion de residentes*), pero no incluye su descripción detallada. Esta descripción sigue la *Plantilla para descripción detallada de casos de uso* aprobada y aplica las decisiones registradas en [extensiones de diseño](../extensiones-diseno.md). No añade funcionalidades a HU-003 / RF-003. La activación de la cuenta por el residente es otro caso de uso (CU-019).

| Campo | Descripción |
|---|---|
| Identificador de caso de uso | CU-003 |
| Nombre | Invitar residente |
| Descripción | Permite al administrador registrar a un nuevo residente, asociarlo a un apartamento disponible y enviarle por correo un enlace para que active su cuenta. |
| Actores | Administrador. |

## Secuencia normal

| Paso | Actor | Software |
|---|---|---|
| 1 | Selecciona "Invitar residente". | |
| 2 | | Muestra el formulario: correo electrónico, nombre completo, apartamento (solo los disponibles) y vigencia (de 1 a 30 días; por defecto 7). También muestra las invitaciones pendientes. |
| 3 | Ingresa los datos, elige el apartamento y confirma. | |
| 4 | | Valida los datos. |
| 5 | | Bloquea el apartamento y comprueba que siga disponible: sin residente activo ni invitación vigente. Una invitación anterior ya vencida se marca como vencida y deja de reservarlo. |
| 6 | | Comprueba el correo: si no existe, crea el usuario residente pendiente de activación, sin contraseña. Si es un residente pendiente cuya invitación venció, lo reutiliza (reinvitación). |
| 7 | | Genera un enlace único, guarda solo su resumen criptográfico, crea la invitación asociada al residente y al apartamento, que queda reservado, y lo registra en la auditoría. |
| 8 | | Envía el correo con el enlace de activación y la fecha de vencimiento, y registra el resultado del envío. |
| 9 | | Muestra "Invitación enviada a … Vence el …". |
| 10 | | El caso de uso termina. El residente continúa en CU-019. |

## Excepciones

| Paso | Software |
|---|---|
| 4 | Si falta un dato o es inválido (correo, nombre, apartamento o vigencia fuera de 1–30), indica los campos que requieren corrección y no crea nada. |
| 5 | Si el apartamento ya no está disponible (ocupado, reservado o eliminado), lo informa y no crea nada. |
| 6 | Si el correo pertenece a una cuenta existente (administrador, residente activo, deshabilitado o eliminado), informa que ya está registrado. Si tiene una invitación vigente, informa que ya existe y que puede reenviarse. En ambos casos no crea nada. |
| 8 | Si el correo no se pudo enviar, la invitación se conserva, el fallo queda registrado y se muestra "La invitación se creó, pero el correo no pudo enviarse." con la opción **Reenviar**. |

## Reenvío

| Paso | Actor | Software |
|---|---|---|
| 1 | Selecciona "Reenviar" en una invitación pendiente. | |
| 2 | | Genera un enlace nuevo (el anterior deja de funcionar), conserva el mismo residente, apartamento y vencimiento, envía el correo y registra el resultado. |
| 3 | | Si la invitación ya venció o fue utilizada, lo informa y no reenvía. |

## Relaciones

| Campo | Descripción |
|---|---|
| CU relacionados | CU-019 Activar cuenta del residente (continuación, por el residente). Usa los apartamentos de CU-013. |
| Precondición | El administrador inició sesión (CU-002) y existe al menos un apartamento disponible (CU-013). |
| Postcondición | Existe un usuario residente pendiente de activación, una invitación vigente que reserva el apartamento y el registro en la auditoría. La cuenta no está activa hasta CU-019. |
