# CU-003 — Invitar residente

> Este archivo tiene dos partes: la **transcripción de la ficha oficial** (Tabla 47 del documento académico) y la **correspondencia con la implementación actual**, que conserva la descripción derivada que se redactó antes de localizar esa ficha. Solo la primera parte es texto del documento académico.

## Transcripción de la ficha oficial

> Transcripción de la ficha oficial: Tabla 47 del documento académico (*PROYECTO DE GRADO*, apartado 13.4.5 «Ficha de especificación de casos de uso»), leyenda «Tabla 47. CU-003 Invitar residente». El documento original no se modifica. El texto se transcribe literalmente, incluidos «6. Solicitar y validar», «5a. No seleccionar» y «8a. Informar» en infinitivo, «10. Envia … correo electronico» sin tildes ni punto final, «invalido» sin tilde, el paso 3 y la excepción 5c sin punto final, y la precondición «El administrador no debe tener una cuenta activa…», que se conserva tal como figura en la ficha. |---|---|

## Correspondencia con la implementación actual

> **Nota histórica (actualizada el 2026-10-10).** La descripción de esta sección se redactó como «caso de uso derivado» antes de localizar y transcribir la ficha oficial. Su nota original decía: «El documento académico nombra CU-003 en la matriz de trazabilidad (módulo *Gestion de residentes*), pero no incluye su descripción detallada.» Esa afirmación ya no es vigente: el documento académico incluye la ficha de CU-003 en la Tabla 47, transcrita arriba (verificada en la auditoría de las fichas de casos de uso del 2026-10-10). La descripción se conserva como correspondencia con la implementación, no como parte de la ficha. Sigue la *Plantilla para descripción detallada de casos de uso* aprobada y aplica las decisiones registradas en [extensiones de diseño](../extensiones-diseno.md). No añade funcionalidades a HU-003 / RF-003. La activación de la cuenta por el residente es otro caso de uso (CU-019).

### Diferencias con la ficha oficial

- **Nombre y actor:** coinciden (Invitar residente; Administrador).
- **Flujo principal:** la ficha separa la vigencia en dos pasos (6. el software la solicita y valida; 7. el administrador la define) y no menciona el nombre del residente. La implementación la incluye en el mismo formulario (de 1 a 30 días, 7 por defecto) junto con el nombre completo, y además bloquea y reserva el apartamento, crea el usuario residente pendiente de activación, guarda solo el resumen criptográfico del enlace, registra la auditoría y el resultado del envío, y ofrece el **reenvío**, que la ficha no describe.
- **Excepciones:** 5a (unidad no seleccionada), 5b (correo inválido) y 7a (vigencia fuera de 1 a 30 días) quedan en la validación del paso 4; 5c (invitación activa para el mismo residente o unidad) corresponde al apartamento no disponible (paso 5) y al correo con invitación vigente (paso 6). La implementación añade el correo de una cuenta existente y el fallo del envío.
- **Precondición:** la ficha dice «El administrador **no** debe tener una cuenta activa…», que se conserva literalmente aunque contradice que sea el administrador quien invita; la implementación exige que el administrador haya iniciado sesión (CU-002) y que exista un apartamento disponible (CU-013). La diferencia no se resuelve aquí.
- **Postcondición:** la implementación añade el usuario pendiente, la reserva del apartamento y la auditoría.
- **Relaciones:** la ficha relaciona «CU-019 Activar cuenta de residente»; la implementación, «CU-019 Activar cuenta del residente» (la matriz, Tabla 39, también dice «del residente») y además CU-013.

### Descripción derivada (implementación)

| Campo | Descripción |
|---|---|
| Identificador de caso de uso | CU-003 |
| Nombre | Invitar residente |
| Descripción | Permite al administrador registrar a un nuevo residente, asociarlo a un apartamento disponible y enviarle por correo un enlace para que active su cuenta. |
| Actores | Administrador. |

#### Secuencia normal

| Paso | Actor | Software |
|---|---|---|
| 1 | Selecciona "Invitar residente". | |
| 2 | | Muestra el formulario: correo electrónico, nombre completo, apartamento (solo los disponibles) y vigencia (de 1 a 30 días; por defecto 7). También muestra las invitaciones pendientes. |
| 3 | Ingresa los datos, elige el apartamento y confirma. | |
| 4 | | Valida los datos. |
| 5 | | Bloquea el apartamento y comprueba que siga disponible: sin residente activo ni invitación vigente. Una invitación anterior ya vencida se marca como vencida y deja de reservarlo. |
| 6 | | Comprueba el correo: si no existe, crea el usuario residente pendiente de activación, sin contraseña. Si es un residente pendiente cuya invitación venció, lo reutiliza (reinvitación). |
| 7 | | Genera un enlace único, guarda solo su resumen criptográfico, crea la invitación asociada al residente y al apartamento, que queda reservado, y lo registra en la auditoría. |
| 8 | | Envía el correo con el enlace de activación y la fecha de vencimiento, y registra el resultado del envío. |
| 9 | | Muestra "Invitación enviada a … Vence el …". |
| 10 | | El caso de uso termina. El residente continúa en CU-019. |

#### Excepciones

| Paso | Software |
|---|---|
| 4 | Si falta un dato o es inválido (correo, nombre, apartamento o vigencia fuera de 1–30), indica los campos que requieren corrección y no crea nada. |
| 5 | Si el apartamento ya no está disponible (ocupado, reservado o eliminado), lo informa y no crea nada. |
| 6 | Si el correo pertenece a una cuenta existente (administrador, residente activo, deshabilitado o eliminado), informa que ya está registrado. Si tiene una invitación vigente, informa que ya existe y que puede reenviarse. En ambos casos no crea nada. |
| 8 | Si el correo no se pudo enviar, la invitación se conserva, el fallo queda registrado y se muestra "La invitación se creó, pero el correo no pudo enviarse." con la opción **Reenviar**. |

#### Reenvío

| Paso | Actor | Software |
|---|---|---|
| 1 | Selecciona "Reenviar" en una invitación pendiente. | |
| 2 | | Genera un enlace nuevo (el anterior deja de funcionar), conserva el mismo residente, apartamento y vencimiento, envía el correo y registra el resultado. |
| 3 | | Si la invitación ya venció o fue utilizada, lo informa y no reenvía. |

#### Relaciones

| Campo | Descripción |
|---|---|
| CU relacionados | CU-019 Activar cuenta del residente (continuación, por el residente). Usa los apartamentos de CU-013. |
| Precondición | El administrador inició sesión (CU-002) y existe al menos un apartamento disponible (CU-013). |
