# CU-001 — Registrar administrador

> **Caso de uso derivado.** El documento académico nombra CU-001 en la matriz de trazabilidad y en el diagrama D01 (Autenticación y control de acceso), pero no incluye su descripción detallada. Esta descripción sigue la *Plantilla para descripción detallada de casos de uso* aprobada y aplica las decisiones registradas en [extensiones de diseño](../extensiones-diseno.md). No añade funcionalidades a HU-001 / RF-001.

| Campo | Descripción |
|---|---|
| Identificador de caso de uso | CU-001 |
| Nombre | Registrar administrador |
| Descripción | Permite crear la cuenta del primer administrador de SoftPh-Académico con su información personal, de contacto y de acceso, mediante un comando controlado del backend. No existe registro público de administradores. |
| Actores | Administrador (ejecuta el comando en el servidor donde opera el sistema). |

## Secuencia normal

| Paso | Actor | Software |
|---|---|---|
| 1 | Ejecuta el comando `python -m app.cli create-admin` en el servidor. | |
| 2 | | Verifica que no exista un administrador activo y solicita los datos. |
| 3 | Ingresa nombre completo, correo electrónico, número de documento (opcional) y teléfono (opcional). | |
| 4 | Ingresa la contraseña y su confirmación (no se muestran en pantalla). | |
| 5 | | Valida los datos, verifica que el correo y el documento no estén registrados, guarda la contraseña cifrada con Argon2id y crea la cuenta activa con el rol ADMINISTRADOR. |
| 6 | | Registra la acción en la auditoría y muestra la confirmación del registro exitoso. |
| 7 | | El caso de uso termina. |

## Excepciones

| Paso | Software |
|---|---|
| 2 | Si ya existe un administrador activo, informa que el comando solo permite crear el primer administrador y termina sin solicitar datos. |
| 5 | Si faltan campos obligatorios o algún dato no cumple las validaciones establecidas, muestra cada validación incumplida y no crea la cuenta. |
| 5 | Si el correo electrónico ya está registrado, informa que el correo ya está registrado y no crea la cuenta. |
| 5 | Si el número de documento ya está registrado, lo informa y no crea la cuenta. |
| 1–5 | Si no es posible conectarse a la base de datos o el comando no se ejecuta en una terminal interactiva, lo informa y no crea la cuenta. |

## Validaciones establecidas

| Dato | Regla |
|---|---|
| Nombre completo | Obligatorio; entre 3 y 150 caracteres; letras, espacios, apóstrofos y guiones. |
| Correo electrónico | Obligatorio; formato válido; se guarda en minúsculas; único. |
| Contraseña | Obligatoria; entre 12 y 128 caracteres; no puede estar formada solo por espacios; no puede ser igual al correo; debe coincidir con la confirmación. No se exigen clases de caracteres. |
| Número de documento | Opcional; entre 5 y 20 letras o dígitos; único. |
| Teléfono | Opcional; entre 7 y 15 dígitos, con «+» inicial opcional. |

## Relaciones

| Campo | Descripción |
|---|---|
| CU relacionados | Ninguno (el diagrama D01 no asocia CU-001 con otros casos de uso). |
| Precondición | No existe un administrador activo en el sistema. El operador tiene acceso al servidor y a la configuración del sistema. |
| Postcondición | Existe una cuenta activa con rol ADMINISTRADOR y contraseña cifrada con Argon2id, y la creación queda registrada en la auditoría. |
