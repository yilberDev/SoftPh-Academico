# HU-003 — Registro de un residente mediante invitación

> Transcripción de la Tabla 3 del documento académico (*PROYECTO DE GRADO*). El documento original no se modifica.

| Campo | Valor |
|---|---|
| Número | HU-003 |
| Nombre de la historia | Registro de un residente mediante invitación. |
| Prioridad en el negocio | Alta |
| Programador responsable | Yilber Sanchez |
| Rol del usuario (Cómo) | administrador, quiero registrar e invitar a un nuevo residente al sistema. |
| Deseo (Qué) | Registrar la información necesaria del residente, asociarlo a una unidad habitacional disponible y enviarle una invitación para completar la activación de su cuenta. |
| Propósito (Para) | Mantener actualizado el registro de residentes y facilitar que cada residente pueda crear de forma segura sus credenciales de acceso al sistema. |
| Observaciones | El administrador será responsable de registrar el residente y asociarlo a una unidad habitacional disponible. La activación de la cuenta y creación de las credenciales será realizada posteriormente por el residente mediante el enlace de invitación enviado a su correo electrónico. |

## Criterios de aceptación

| No. | Contexto | No. | Evento |
|---|---|---|---|
| 1 | Acceso al registro de residentes. | 1 | Cuando el administrador ingrese correctamente al sistema y seleccione la opción para crear residente. |
| | | 2 | El sistema debe mostrar el formulario para registrar e invitar al nuevo residente. |
| 2 | Selección de unidad habitacional. | 1 | El administrador debe poder seleccionar una unidad habitacional disponible desde el formulario. |
| | | 2 | El sistema no debe permitir seleccionar una unidad que ya se encuentre asignada a otro residente, cuando la regla de negocio establecida indique que la unidad debe estar disponible. |
| 3 | Registro de información. | 1 | El administrador debe ingresar el correo electrónico del residente y la información requerida para generar la invitación. |
| | | 2 | El sistema debe validar que los datos obligatorios sean correctos antes de continuar. |
| 4 | Validación de duplicados. | 1 | Cuando el administrador intente registrar una invitación utilizando un correo electrónico que ya tenga una cuenta o invitación activa, según las reglas definidas. |
| | | 2 | El sistema no debe permitir generar un registro duplicado y debe informar al administrador de la situación. |
| 5 | Generación de invitación. | 1 | Cuando los datos proporcionados sean válidos y exista una unidad disponible. |
| | | 2 | El sistema debe generar la invitación correspondiente y asociarla al residente y a la unidad seleccionada. |
| 6 | Envío de invitación. | 1 | Cuando la invitación sea generada correctamente. |
| | | 2 | El sistema debe enviar un enlace de invitación al correo electrónico proporcionado por el administrador. |
| 7 | Registro exitoso | 1 | Cuando la invitación sea creada y enviada correctamente. |
| | | 2 | El sistema debe mostrar una confirmación de que el proceso de registro e invitación fue realizado correctamente. |
| 8 | Error en el formulario. | 1 | Cuando algún campo obligatorio no sea diligenciado o contenga información inválida. |
| | | 2 | El sistema no debe permitir continuar y debe indicar los campos que requieren corrección. |

## Estado de cumplimiento

HU-003 cubre **solo el flujo del administrador**: registrar e invitar. La activación de la cuenta (abrir el enlace, crear la contraseña, activar el usuario y crear la residencia) la hace el residente en **[HU-019](HU-019.md)**. Ver [extensiones de diseño](../extensiones-diseno.md) (HU-003).

| Criterio | Estado | Detalle |
|---|---|---|
| 1 | Cumplido | "Invitar residente" en el panel y en el menú del administrador lleva a `/admin/residents/invite`, protegida para ADMINISTRADOR. |
| 2 | Cumplido | La lista solo ofrece apartamentos disponibles (`GET /api/v1/units/available`). La regla establecida: el apartamento está activo y no tiene residente activo ni invitación vigente. El backend la vuelve a comprobar al crear: enviar a mano el `unit_id` de un apartamento ocupado o reservado responde 409 `UNIT_NOT_AVAILABLE`. |
| 3 | Cumplido | Correo, nombre completo, apartamento y vigencia (de 1 a 30 días, criterio 1.4 de HU-019). Se validan antes de guardar con las mismas reglas de HU-001 para el correo y el nombre. |
| 4 | Cumplido | Un correo de una cuenta existente (administrador, residente activo, deshabilitado o eliminado) responde 409 `EMAIL_ALREADY_REGISTERED`. Un correo con una invitación vigente responde 409 `INVITATION_ALREADY_PENDING`. Si la invitación anterior venció, se reinvita al mismo usuario pendiente sin duplicarlo. |
| 5 | Cumplido | Se crea el usuario RESIDENTE en `PENDING_ACTIVATION` (sin contraseña) y una invitación `PENDING` asociada al usuario y al apartamento, que queda reservado. |
| 6 | Cumplido | Se envía un correo con el enlace `…/activate-account#token=…` y el vencimiento en hora de Colombia. En desarrollo se verifica en Mailpit. La página del enlace (`/activate-account`) es de HU-019. |
| 7 | Cumplido | "Invitación enviada a … Vence el …". Si el correo no se pudo enviar, la invitación se conserva y se muestra "La invitación se creó, pero el correo no pudo enviarse." con la opción **Reenviar**. |
| 8 | Cumplido | Con datos ausentes o inválidos no se crea nada y se indica cada campo a corregir (en la interfaz y con el detalle por campo de la API). |
