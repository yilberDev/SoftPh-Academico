# HU-013 — Gestión de unidades residenciales

> Transcripción de la Tabla 13 del documento académico (*PROYECTO DE GRADO*). El documento original no se modifica.

| Campo | Valor |
|---|---|
| Número | HU-013 |
| Nombre de la historia | Gestión de unidades residenciales |
| Prioridad en el negocio | Alta |
| Programador responsable | Yilber Sanchez |
| Rol del usuario (Cómo) | Administrador, quiero gestionar las unidades residenciales registradas en el sistema. |
| Deseo (Qué) | Crear, consultar, actualizar y eliminar la información de las unidades residenciales. |
| Propósito (Para) | Mantener organizada y actualizada la información de las unidades que conforman la Urbanización San Joaquin. |
| Observaciones | La información de las unidades residenciales debe mantenerse actualizada para facilitar la gestión de residentes y la administración de la propiedad. |

## Criterios de aceptación

| No. | Contexto | No. | Evento |
|---|---|---|---|
| 1 | Registro de unidades | 1 | El administrador debe poder registrar una nueva unidad residencial proporcionando la información requerida. |
| | | 2 | El sistema debe validar la información ingresada antes de almacenar el registro. |
| 2 | Consulta de unidades | 1 | El administrador debe poder visualizar el listado de unidades residenciales registradas. |
| | | 2 | El sistema debe mostrar la información relevante de cada unidad. |
| 3 | Actualización de unidades. | 1 | El administrador debe poder seleccionar una unidad y modificar la información registrada. |
| | | 2 | El sistema debe guardar los cambios realizados y reflejarlos en la información de la unidad. |
| 4 | Eliminación de unidades. | 1 | El administrador debe poder seleccionar una unidad para eliminarla del registro. |
| | | 2 | El sistema debe solicitar la confirmación antes de realizar la eliminación. |
| 5 | Validación de información. | 1 | Cuando el administrador intente registrar o actualizar una unidad con información incompleta o inválida. |
| | | 2 | El sistema no debe permitir guardar la información y debe indicar los datos que requieren corrección. |

## Estado de cumplimiento

La unidad residencial es el **apartamento**, ubicado en la estructura Bloque → Torre → Apartamento de la urbanización (ver [extensiones de diseño](../extensiones-diseno.md), HU-013).

| Criterio | Estado | Detalle |
|---|---|---|
| 1.1 | Cumplido | El administrador registra bloques, torres y apartamentos indicando su número (`/admin/blocks`, `/admin/blocks/[id]`, `/admin/towers/[id]`). |
| 1.2 | Cumplido | El backend valida el número (entero positivo), que el padre exista y esté activo, y que el número no esté repetido en su contexto, antes de guardar. |
| 2.1 | Cumplido | Listados por nivel con navegación jerárquica: bloques → torres del bloque → apartamentos de la torre. |
| 2.2 | Cumplido | Cada unidad muestra su identificador oficial derivado (p. ej., `B1-TO2-APTO-104`), y bloques y torres muestran sus torres y apartamentos activos. |
| 3.1 | Cumplido | "Editar" permite corregir el número de un bloque, una torre o un apartamento. |
| 3.2 | Cumplido | El cambio se guarda (con control de versión) y se refleja en el identificador de la unidad y de sus descendientes. Antes de confirmar un cambio que afecta a descendientes, se muestra una advertencia. |
| 4.1 | Cumplido | "Eliminar" en cada fila (borrado lógico; el historial se conserva). |
| 4.2 | Cumplido | Diálogo de confirmación antes de eliminar. |
| 5.1 / 5.2 | Cumplido | Con datos incompletos o inválidos no se guarda nada y se indica el campo y el motivo (p. ej., "El número debe ser un entero positivo (1 o mayor)."). Duplicados y conflictos se informan con un mensaje claro (409). |
