# HU-019 — Invitación y activación de cuenta del residente

> Transcripción de la Tabla 19 del documento académico (*PROYECTO DE GRADO*). El documento original no se modifica; las erratas se conservan.

| Campo | Valor |
|---|---|
| Número | HU-019 |
| Nombre de la historia | Invitación y activación de cuenta del residente |
| Prioridad en el negocio | Alta |
| Programador responsable | Yilber Sanchez |
| Rol del usuario (Cómo) | Administrador, quiero invitar a un residente a registrarse en el sistema y asociarlo a una unidad habitacional. |
| Deseo (Qué) | Crear una invitación indicando la unidad habitacional, el correo electrónico del residente y el período de vigencia de la invitación. |
| Propósito (Para) | Permitir que el residente complete de forma segura el proceso de registro y active su cuenta para acceder al sistema. |
| Observaciones | La invitación debe estar asociada a una unidad habitacional disponible y contar con una fecha de expiración definida. El alcance de invitación será enviado al correo electrónico proporcionado por el administrador y permitirá al residente completar su registro y establecer sus credenciales de acceso. |

## Criterios de aceptación

| No. | Contexto | No. | Evento |
|---|---|---|---|
| 1 | Creación de invitación. | 1 | Cuando el administrador seleccione la opción para crear un nuevo residente, el sistema debe mostrar el formulario de invitación. |
| | | 2 | El administrador debe poder seleccionar una unidad habitacional disponible desde una lista. |
| | | 3 | El administrador debe ingresar el correo electrónico del residente. |
| | | 4 | El administrador debe definir la vigencia de la administración entre un mínimo de 1 día y un máximo de 30 días. |
| 2 | Validación de la invitación. | 1 | Cuando el administrador intente crear una invitación sin seleccionar una unidad habitacional disponible o sin proporcionar un correo electrónico válido. |
| | | 2 | El sistema no debe permitir generar la invitación y debe indicar los datos que requieren corrección. |
| 3 | Envío de la invitación. | 1 | Cuando la información de la invitación sea válida. |
| | | 2 | El sistema debe generar un enlace de invitación único y asociado al residente y a la unidad seleccionada. |
| 4 | Aceptación de la invitación. | 1 | Cuando el residente acceda al enlace recibido dentro del período de vigencia establecido. |
| | | 2 | El sistema debe permitir al residente completar la información requerida para activar su cuenta. |
| 5 | Creación de credenciales | 1 | Cuando el residente complete correctamente el proceso de activación. |
| | | 2 | El sistema debe permitir establecer una contraseña para su cuenta. |
| | | 3 | El sistema debe asociar la cuenta del residente con la unidad habitacional asignada por el administrador. |
| 6 | Activación de la cuenta. | 1 | Cuando el residente complete correctamente el proceso de registro. |
| | | 2 | El sistema debe activar la cuenta y permitirle iniciar sesión con sus nuevas credenciales. |
| 7 | Invitación expirada | 1 | Cuando el residente intente acceder al enlace después de finalizar el período de vigencia. |
| | | 2 | El sistema no debe permitir completar la activación mediante el enlace expirado e informará qie la invitación ya no se encuentra vigente. |
| 8 | Estado de la invitación. | 1 | Cuando una invitación haya sido utilizada correctamente por el residente. |
| | | 2 | El sistema debe actualizar su estado para evitar que el mismo enlace pueda utilizarse nuevamente. |

## Estado de cumplimiento

Reparto aprobado (ver [extensiones de diseño](../extensiones-diseno.md)): **HU-003 = invitación** (lo que hace el administrador), **HU-019 = activación** (lo que hace el residente), **HU-007 = inicio de sesión del residente**. Los criterios 1 a 3 describen la parte del administrador y se cumplen con la implementación de HU-003; HU-019 consume esa invitación.

| Criterio | Estado | Detalle |
|---|---|---|
| 1 (1.1–1.4) | Cumplido en HU-003 | Formulario "Invitar residente", lista de apartamentos disponibles, correo y vigencia de 1 a 30 días. Ver [HU-003](HU-003.md), criterios 1 a 3. |
| 2 (2.1–2.2) | Cumplido en HU-003 | Sin apartamento disponible o con un correo inválido no se genera la invitación y se indican los campos a corregir. Ver HU-003, criterios 2, 3 y 8. |
| 3 (3.1–3.2) | Cumplido en HU-003 | Enlace único (token de 256 bits; en la BD solo su SHA-256) asociado al residente y al apartamento, enviado por correo. HU-019 no vuelve a enviarlo. |
| 4 | Cumplido | El enlace `/activate-account#token=…` verifica la invitación (`POST /api/v1/resident-invitations/verify`). Si está vigente, muestra nombre, correo, apartamento y vencimiento, y el formulario: documento (obligatorio), teléfono (opcional), contraseña y confirmación. |
| 5 | Cumplido | 5.2: la contraseña (12 a 128 caracteres, las reglas de HU-001) se guarda con Argon2id. 5.3: se crea la residencia (`resident_units`) con el usuario y el apartamento de la invitación, nunca con datos enviados por el cliente. |
| 6 | Cumplido (6.2 con HU-007) | La cuenta queda activa (`ACTIVE`) y la pantalla final enlaza al login. "Permitirle iniciar sesión con sus nuevas credenciales" se cumple con [HU-007](HU-007.md): el login único admite residentes activos. La activación en sí no crea sesión. |
| 7 | Cumplido | Un enlace vencido no permite activar: la invitación pasa a `EXPIRED` y se informa "La invitación ya no se encuentra vigente" (410). No se activa el usuario ni se crea la residencia; la administración puede reinvitar (HU-003). |
| 8 | Cumplido | Tras la activación la invitación queda `USED` (con `used_at`) y el mismo enlace responde "Este enlace ya fue utilizado" (410). Un uso simultáneo del mismo enlace activa la cuenta una sola vez. |

El criterio 6.2 quedó cubierto al implementarse HU-007.
