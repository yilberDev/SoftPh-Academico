# HU-004 — Registro de pagos de residentes

> Transcripción de la Tabla 4 del documento académico (*PROYECTO DE GRADO*). El documento original no se modifica.

| Campo | Valor |
|---|---|
| Número | HU-004 |
| Nombre de la historia | Registro de pagos de residentes |
| Prioridad en el negocio | Alta |
| Programador responsable | Yilber Sanchez |
| Rol del usuario (Cómo) | Administrador, quiero registrar los pagos realizados por los residentes. |
| Deseo (Qué) | Registrar los pagos en el sistema con detalles como monto, método de pago y fecha. |
| Propósito (Para) | Llevar un control claro y actualizado de los pagos de administración. |
| Observaciones | La administración desea registrar los pagos realizados por los residentes y mantener actualizada su información financiera. |

## Criterios de aceptación

| No. | Contexto | No. | Evento |
|---|---|---|---|
| 1 | Ingreso de datos | 1 | El sistema debe permitir ingresar el monto del pago en formato numérico. |
| | | 2 | El administrador debe seleccionar el método de pago entre las opciones disponibles: efectivo, tarjeta o transferencia. |
| | | 3 | La fecha del pago debe ser seleccionada mediante un calendario o ingresada manualmente. |
| | | 4 | Si se deja un campo obligatorio vacío, el sistema mostrará un mensaje de error indicando el campo que falta. |
| 2 | Actualización del sistema | 1 | Al guardar el pago, el sistema debe actualizar automáticamente el estado de cuenta del residente, reflejando el nuevo saldo. |
| | | 2 | La transacción debe registrarse con la fecha y hora de su ingreso. |
| 3 | Generación de recibo | 1 | El sistema debe generar un recibo que incluya el nombre del residente, unidad donde vive, monto, método de pago, concepto del pago( mensualidad, mora, penalización o entre otros) y fecha de pago. |
| | | 2 | El recibo debe enviarse automáticamente al correo electrónico del residente en formato PDF adjunto. |
| 4 | Interfaz amigable | 1 | El administrador debe poder consultar un resumen de los pagos registrados en una tabla que incluya nombre del residente, concepto del pago, monto, método de pago y estado. |
| | | 2 | La tabla debe ser ordenable y filtrable por fecha y residente. |

## Alcance

Registro **manual** de pagos por el administrador (sin dinero real ni pasarelas externas). Las decisiones de diseño aprobadas (modelo financiero, FIFO, saldo a favor, separación de fechas, recibo después de confirmar el pago) están en [extensiones de diseño](../extensiones-diseno.md) (HU-004). No incluye: pago electrónico (HU-010), generación de cuotas o mora, anulación de pagos, uso posterior del saldo a favor, estado de cuenta completo (HU-011, HU-014) ni reportes (HU-012).

## Estado de cumplimiento

| Criterio | Estado | Detalle |
|---|---|---|
| 1.1 | Cumplido | Monto numérico de hasta 2 decimales, mayor que cero, sin redondeos (un valor con más decimales se rechaza). |
| 1.2 | Cumplido | Método: Efectivo, Tarjeta o Transferencia; ningún otro valor es aceptado por el servidor. |
| 1.3 | Cumplido | Fecha con calendario o escrita (`AAAA-MM-DD`); por defecto, hoy en Bogotá; nunca posterior a hoy. |
| 1.4 | Cumplido | Cada campo obligatorio vacío o inválido muestra su propio mensaje junto al campo, tanto en el navegador como en la respuesta del servidor (residente, monto, método, concepto, descripción cuando el concepto es «Otro», fecha). |
| 2.1 | Cumplido | Al guardar, el pago se aplica automáticamente a las obligaciones pendientes de la unidad (FIFO) y la confirmación muestra el valor aplicado, el saldo a favor, el estado del pago y el saldo resultante de la unidad (pendiente y a favor), calculados a partir de cargos, pagos y aplicaciones. |
| 2.2 | Cumplido | Se guarda la fecha y hora de registro (`registered_at`, UTC; se muestra en hora de Colombia), separada de la fecha del pago. |
| 3.1 | Cumplido | Recibo PDF con número (`RC-00000001`), nombre del residente, unidad, monto, método, concepto, fecha del pago y fecha y hora de registro, tomados de los datos guardados con el pago (no cambian si después cambia el residente o la unidad). |
| 3.2 | Cumplido | Se envía automáticamente al correo actual del residente como PDF adjunto (Mailpit en desarrollo). Si el envío falla, el pago queda registrado y se informa por separado. |
| 4.1 | Cumplido | `/admin/payments` muestra el resumen: nombre, concepto, monto, método, fecha y estado (Aplicado, Aplicado parcialmente, Saldo a favor), con el número de recibo y la unidad. |
| 4.2 | Cumplido | Ordenable por fecha, residente, monto, concepto, método y estado; filtrable por residente (nombre o documento) y por rango de fechas; paginado en el servidor. |
