# HU-005 — Revisar y gestionar feedback de residentes

| Campo | Valor |
|---|---|
| Número | HU-005 |
| Nombre de la historia | Revisar y gestionar feedback de residentes |
| Prioridad en el negocio | Alta |
| Programador responsable | Yilber Sanchez |
| Rol del usuario (Cómo) | administrador, quiero revisar el feedback recibido de los residentes. |
| Deseo (Qué) | Gestionar las quejas, solicitudes y sugerencias de manera eficiente. |
| Propósito (Para) | Mejorar la calidad de la gestión administrativa y responder adecuadamente a las inquietudes de los residentes. |
| Observaciones | La administración debe poder consultar, gestionar y realizar seguimiento a los feedback registrados por los residentes. |

## Criterios de aceptación

| No. | Contexto | No. | Evento |
|---|---|---|---|
| 1 | Listado de feedback | 1 | El administrador debe poder consultar un listado que incluya el nombre del residente, fecha, estado y asunto. |
| | | 2 | El listado debe ser paginado y permitir al administrador navegar entre sus registros. |
| 2 | Detalles del feedback | 1 | Al seleccionar un feedback, el sistema debe mostrar los detalles del mensaje y la información correspondiente del residente. |
| | | 2 | El sistema debe permitir al administrador responder el feedback mediante la interfaz. |
| 3 | Respuesta y gestión | 1 | El administrador debe poder marcar el feedback como resuelto y registrar una nota sobre la gestión realizada. |
| | | 2 | El sistemas debe enviar una notificación al residente indicando que su feedback ha sido revisado e incluyendo la respuesta del administrador. |
| 4 | Registro de acciones | 1 | El sistema debe registrar las acciones realizadas por el administrador sobre el feedback, incluyendo respuesta y cambios de estado. |
| | | 2 | El registro debe incluir la fecha y hora de cada acción para facilitar su consulta y auditoría. |

## Alcance

Gestión del feedback **por el administrador**. El residente registra y consulta su feedback en HU-009 (no implementada todavía: no hay endpoints de residente). Las notificaciones usan el envío de correo existente; HU-017 podrá centralizarlas. Las decisiones que interpretan el documento (estados, respuesta separada de la nota, búsqueda, concurrencia) están en [extensiones de diseño](../extensiones-diseno.md) (HU-005) y no forman parte del texto académico.

## Estado de cumplimiento

| Criterio | Estado | Detalle |
|---|---|---|
| 1.1 | Cumplido | `/admin/feedback` muestra residente, asunto («Sin asunto» si el residente no lo indicó), fecha y estado (Pendiente o Resuelto), con acceso al detalle. |
| 1.2 | Cumplido | Paginación en el servidor (10, 25 o 50 por página) con Anterior y Siguiente; además, filtro por estado, búsqueda por residente o asunto y orden por columna (extensiones). |
| 2.1 | Cumplido | El detalle muestra el mensaje original (no editable), el asunto, la fecha y el residente: nombre, correo y unidad residencial actual (o «Sin unidad residencial actual»). |
| 2.2 | Cumplido | El administrador escribe y guarda la respuesta desde el detalle mientras el feedback está pendiente; puede reemplazarla mientras siga pendiente. |
| 3.1 | Cumplido | «Marcar como resuelto», con confirmación previa, exige una nota de resolución (interna) y cambia el estado a Resuelto con su fecha y hora. |
| 3.2 | Cumplido | Al responder y al resolver se envía un correo al residente indicando que su feedback fue revisado, con la respuesta del administrador cuando existe. Si se resuelve sin respuesta escrita, el correo informa la gestión realizada sin inventar una respuesta; la nota interna nunca se envía. Un fallo del correo no deshace el cambio. |
| 4.1 | Cumplido | Se registran en la auditoría la respuesta, la resolución (cambio de estado) y el resultado de cada notificación, con el administrador que actuó. |
| 4.2 | Cumplido | Cada acción guarda su fecha y hora; el detalle muestra el historial (fecha y hora, acción y administrador), obtenido de la auditoría. |
